# 검색 방식, RAG, 그리고 넘어갈 때

[README](../../README.ko.md) | [English](../SEARCH-AND-RAG.md) | 한국어

## 짧은 답

RAG(검색 증강 생성)는 먼저 검색하고, 찾은 것을 AI가 읽고 답하게 하는 구조입니다. 이 넓은 뜻으로는 knowledge-scout도 RAG입니다. 흔한 방식과 다른 점은 두 가지입니다.

- **무엇을 찾는가.** 원문 조각이 아니라 짧은 지식 카드(제목, 다루는 문제, 한계, 근거 종류, 태그)를 찾습니다.
- **어떻게 찾는가.** 통제 어휘 태그와 글자 일치(키워드 검색)로 찾습니다. 임베딩도 벡터 DB도 없습니다. 후보는 AI 세션이 읽고 판정하므로, 서버는 일치 개수만 세고 모델이 필요 없습니다.

그래서 물음은 "RAG냐 아니냐"가 아니라 "후보를 무엇으로 찾느냐"입니다. 이 문서는 이 선택이 맞는 조건, 안 맞는 곳, 그리고 무엇으로 넘어가는지를 적습니다.

## 쉬운 말로 푼 용어

| 용어 | 뜻 | 잘하는 것 | 못하는 것 |
| --- | --- | --- | --- |
| 키워드 검색(BM25) | 질의와 단어가 겹치는 문서를 찾는다. 드문 단어가 겹칠수록 점수가 높다 | 제품 이름, 정확한 용어 | 같은 뜻을 다른 말로 쓴 경우 |
| 통제 어휘(태그) | 정해 둔 용어 목록에서만 태그를 단다 | 표기가 흔들려도 같은 태그로 모은다 | 목록을 사람이 관리해야 한다. 목록과 다른 말로 물으면 못 찾는다 |
| 임베딩(의미 검색) | 문장을 숫자 묶음으로 바꿔 뜻이 가까운 문장을 찾는다 | 바꿔 말하기, 언어 건너기(한국어 질문 ↔ 영어 글) | 드문 고유명사와 정확한 일치. 모델이 필요하고, 모델을 바꾸면 전부 다시 계산한다. 왜 걸렸는지 설명하기 어렵다 |
| 벡터 DB | 그 숫자 묶음을 대량으로 빨리 찾아 주는 저장소 | 수십만~수백만 건 | 작은 규모에는 필요 없다. Redis에도 이 기능이 있다 |
| 하이브리드 검색 | 키워드 검색과 의미 검색의 결과를 합친다 | 서로의 약점을 메운다 | 부품이 늘어난다 |
| 재순위 | 찾아 온 후보를 더 강한 모델이 다시 줄 세운다 | 정밀도 | 비용과 시간. 여기서는 세션 모델의 A/B/C 판정이 이 역할이다 |

## 이 방식이 잘 맞는 조건

- 카드가 수백~수천 장이고, 한 사람이나 작은 팀이 관리한다. 색인 재생성이 빠르고 고칠 것이 파일뿐이다.
- 질의에 기술 이름이 들어간다. 태그와 글자 일치가 가장 잘하는 일이다.
- 왜 걸렸는지 보여 줘야 한다. 일치한 용어와 글자를 그대로 돌려주고, 같은 입력에는 같은 결과가 나온다.
- 서버에 모델, API 키, GPU를 두고 싶지 않다.
- 판정을 이미 쓰고 있는 AI 세션이 한다.

## 한계와 측정 조건

- **쓰는 말이 다르면 놓칩니다.** 자체 평가에서 기대한 카드 59건 중 47건(79.7%)이 후보 40장 안에 들었습니다. 놓친 12건은 일치한 용어도 일치한 글자도 전혀 없었습니다. 다른 용도로 기법을 빌려 쓰려는 질의는 24건 중 17건(70.8%)을 찾았습니다.
- **이 수치의 조건.** 질의 50개, 기대 카드 59건, 비공개 평가셋, 판정자 1명이 1회 수행했으므로 오차가 큽니다(약 9%p). 검색 용어는 어휘 목록을 보고 골랐습니다. 실제 `/ks:search` 스킬은 이 목록을 보여 주지 않으므로 실사용 값은 더 낮을 가능성이 높고, 재 본 적이 없습니다. 기록이 남은 실사용 1회에서는 질의 용어 12개 중 9개가 어휘에 없었습니다.
- **카드에 없으면 못 찾습니다.** 글을 카드로 줄이면서 빠진 세부는 어떤 카드 검색으로도 못 찾습니다. 카드로 만들지 않은 글은 아예 찾지 못합니다.
- **어휘를 돌봐야 합니다.** 새 카드가 들어오면 새 용어가 생기고, 어휘를 고치면 색인을 다시 만들고 MCP 서버를 다시 띄워야 합니다.
- **순위는 일치한 용어의 개수입니다.** 흔한 용어 3개가 겹친 글이, 드물고 결정적인 용어 1개가 겹친 글보다 앞설 수 있습니다. 질의당 걸리는 카드가 적을 때는 드러나지 않고, 카드가 훨씬 늘면 영향이 있을 수 있습니다. 재지 않았습니다.
- **검색 한 번에 품이 듭니다.** 측정한 1회는 58초에 모델 사용료 약 0.60달러였습니다. 사람이 하루에 몇 번 쓰는 용도입니다.

## RAG나 벡터 DB로 넘어갈 신호

기준값은 제안이며 측정으로 확인된 결론이 아닙니다. 재기 전에 먼저 고정해 두세요.

| 보이는 것 | 넘어갈 곳 |
| --- | --- |
| 새 실제 질의 묶음에서, 질의 문장을 점수에 합친 뒤에도 기대 카드가 후보 40장 안에 드는 비율이 85% 미만 | 카드의 짧은 글(제목, 문제, 요약)을 임베딩해 같은 Redis에 넣는다 |
| 바꿔 쓴 질의가 원본보다 5%p 넘게 낮다. 또는 모델이 어휘 목록을 본 뒤에도 질의 용어 대부분이 어휘에 없다 | 임베딩 |
| 기술 이름 없이 상황만 설명하거나, 다른 분야의 기법을 빌리려는 질의가 잦다 | 임베딩. 그래도 모자라면 원문 조각 검색 |
| 카드가 없는 글, 또는 어떤 카드에도 없는 세부를 찾아야 한다 | 원문 조각 임베딩(좁은 뜻의 RAG) |
| 한국어 질문으로 영어 글을 바로 찾아야 한다 | 다국어 임베딩. 글자 일치는 언어를 건너지 못하고, Redis 검색 엔진의 어간 처리 목록에도 한국어가 없다 |
| 검색할 때 후보 40자리가 자주 다 찬다 | 일치 개수 대신 점수(BM25나 임베딩 거리)로 순위를 매긴다 |
| 카드 약 2만 장, 또는 주에 수백 편이 들어온다 | 먼저 순위와 색인 갱신 방식을 다시 본다 |
| 벡터 100만 개 이상, 또는 초당 수십 건의 질의 | Redis의 HNSW 색인. 그다음에야 전용 벡터 DB |

한 줄로 줄이면 이렇습니다. 재서 "말이 달라서 놓친다"가 확인되면 임베딩, "카드에 없어서 놓친다"가 확인되면 원문 검색, "100만 건이 넘는다"가 되면 벡터 DB입니다. 실제 검색 기록도 남기세요. 기록이 없으면 이 신호를 볼 수 없습니다.

## 같은 Redis 안에서의 전환 경로

Redis에 이미 필요한 부품이 있습니다. 공식 문서는 벡터 100만 개 미만이면 FLAT 색인을 권하고, `FT.HYBRID`(키워드와 벡터를 한 질의로, Redis 8.4.0부터)를 제공한다고 적습니다. 위의 측정이 필요하다고 할 때만 따를 순서는 다음과 같습니다.

1. 임베딩 없이 후보 관문을 넓힌다. 모델에게 어휘 목록을 보여 주고, 질의 문장도 점수에 쓴다.
2. 카드의 짧은 글을 임베딩해 벡터 결과와 키워드 결과를 합친다. 이 단계에서 서버에 임베딩 모델이나 API 호출이 생깁니다. 지금은 필요 없는 것입니다.
3. "카드에 없다"나 "언어" 신호가 뜰 때만 원문 조각을 검색한다.

**백로그 공지: `FT.HYBRID`(키워드+벡터 하이브리드 검색)는 백로그이며 추후 제공할 예정입니다.** knowledge-scout는 지금 이 명령도, 어떤 벡터 검색도 쓰지 않습니다.

## 외부 참고 자료

- BEIR 벤치마크(Thakur 외, 2021): BM25는 학습하지 않은 분야에서도 강한 기준선입니다. https://arxiv.org/abs/2104.08663
- Anthropic, Contextual Retrieval(2024-09-19): 임베딩에 BM25를 합치고 재순위를 더하면, 벤더 자체 시험에서 상위 20개 검색 실패율이 5.7%에서 1.9%로 내려갔습니다. 지식 베이스가 약 20만 토큰보다 작으면 전체를 프롬프트에 넣으라고 권합니다. https://www.anthropic.com/news/contextual-retrieval
- Li 외(2024), RAG와 긴 문맥 LLM: 긴 문맥이 평균 성능은 높고 RAG는 비용이 낮습니다. https://arxiv.org/abs/2407.16833
- LaRA(2025): 모델, 문맥 길이, 과제에 따라 낫다는 쪽이 달라지며 만능 답은 없습니다. https://arxiv.org/abs/2502.09977
- Redis 벡터: 작은 데이터(벡터 100만 개 미만)는 FLAT 색인, 더 크면 HNSW. https://redis.io/docs/latest/develop/ai/search-and-query/vectors/
- Redis `FT.HYBRID`: 전문 검색과 벡터 검색을 한 명령으로, 8.4.0부터. https://redis.io/docs/latest/commands/ft.hybrid/
- Redis 어간 처리: 지원 언어 목록(2026-11-11 확인 시 한국어 없음). https://redis.io/docs/latest/develop/ai/search-and-query/advanced-concepts/stemming/

대부분 벤더 시험이거나 작은 연구입니다. 증명이 아니라 단서로 읽으세요. 가장 좋은 근거는 내 질의로 직접 재 보는 것입니다.
